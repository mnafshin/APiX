# Documentation Structure

Proposed documentation information architecture for APiX:

Sections
- Getting Started — task-oriented quickstarts (docs/getting-started.md)
- How-to Guides — step-by-step workflows and recipes (docs/how-to/)
- Concepts — conceptual explanations and diagrams (docs/concepts/)
- Reference — APIs, CLI flags, protobufs, config (docs/reference/)
- Architecture / Decisions — deeper system design notes (docs/architecture.md)

Guidelines
- Each page should declare its intent: tutorial, how-to, concept, or reference
- Cross-link liberally; each page should point to what to read next
- Keep quickstarts short and actionable; reserve concepts for explanation
